Build

No mystery notebook.

A reviewer shouldn't have to guess what happened. I split the work into data, SQL, code, reports, charts, and notes.

01

Generate data

I create safe sample rows with category, region, channel, price, discount, and campaign fields.

02

Clean rows

03

Summarize sales

04

Model carefully

Tools

Simple tools, clear reasons.

This isn't about throwing the fanciest model at the problem. It's about moving from rows to numbers to a dashboard someone can understand.

SQL Sales data usually sits in tables, so SQL belongs here.
pandas Good for cleaning rows, grouping data, making new fields, and saving tables.
Ridge regression A steady forecast baseline when features are related to each other.
LightGBM A stronger tree-based model. I tested it, but it didn't win on this run.
K-means Groups categories into high-value growing, stable core, campaign-responsive, and low-volume niche.
Bootstrap CI Gives a range for the campaign comparison without pretending it's proof of cause and effect.

Limits

What this is, and what it isn't.

This is commercial analytics with generated public data. It is not a clinical project, not a production system, and not proof of campaign lift.

Data The data is generated so the repo can be shared and checked safely.
Campaign comparison Campaign rows are compared, but not treated as causal proof.
Domain No patient, drug efficacy, safety, or clinical recommendation claims.
